# ADR-0006 涨停棱镜页：涨停池 + 概念聚合 + 本地按日快照

日期：2026-11-07
状态：已采纳

## 背景

用户要求照经传多赢（n8n8.cn）的「涨停棱镜」在左侧导航加一页，功能与界面与源页面一致。
源页面四个面板：

1. **涨停周期表**：近 N 个交易日 × 每日涨停数 Top10 主题的网格，单元格右上角是该主题
   近 20 日涨停总数；
2. **涨停棱镜图**：黄线 = 沪深 A 股涨停总数、红色面积 = 所选主题涨停数；
   下方红色渐变条（0~3 / 3~5 / 5~10 / 10~15 / 15 以上）是**当日涨停家数**的色阶；
3. **主题榜**：主题的涨停数、涨幅、主力净买额、3 日/5 日主力、主力占比，带「热 / 扩张」标签；
4. **个股池**：炒作涨停 / 板块涨停 / 板块炸板 / 板块烂板 + 涨停原因、连板数、封板金额。

## 决策

### 1. 数据源：东财为主体，同花顺只补「涨停原因」

| 用途 | 接口 | 关键点 |
|---|---|---|
| 涨停池、炸板池 | `push2ex.eastmoney.com/getTopicZTPool` / `getTopicZBPool` | `tc` 总数、`lbc` 连板、`fund` 封单额、`zbc` 炸板次数、`hybk` 行业 |
| 概念板块 + 资金四列 | `push2/clist?fs=m:90 t:3` | `f3` 涨幅、`f62` 今日主力、`f184` 今日占比、`f267` 3 日主力、`f164` 5 日主力 |
| 个股所属概念 | `datacenter RPT_F10_CORETHEME_BOARDTYPE` | 每只涨停/炸板股 1 请求 |
| 涨停原因 | 同花顺 `dataapi/limit_up/limit_up_pool` 的 `reason_type` | 失败即降级为东财 `hybk` 行业名 |

**不让同花顺当主题维度**：它的概念代码（885xxx）与东财（BKxxxx）不同源，跨源做名称映射
既要维护别名表、又会污染资金列（资金只有东财给）。改成「东财概念 = 主题」后，
主题榜的资金四列天然同一套板块代码，不需要任何映射。

### 2. 概念归属必须用 `IS_PRECISE == "1"`

`RPT_F10_CORETHEME_BOARDTYPE` 返回的是「所属板块」大杂烩：行业、地域、财务特征、
东财特色数据（`最近多板` / `东方财富热股` / `连续亏损` / `QFII新进` / `基金减仓` …）全在里面。
只按「名字命中概念板块名单」过滤时，当日 Top1 会被 `最近多板`（12 家）、
`东方财富热股`（11 家）这种噪音霸榜。实测 `IS_PRECISE == "1"` 才是真正的精确概念
（每只票 4~16 个，全部命中概念名单；噪音项清一色是 `0` 或 `null`）。
名字黑名单只作为第二道保险（地域 `*板块`、`昨日*`、`*重仓`、财务特征）。

### 3. `clist` 的 `pz` 被上游截到 100，必须翻页

传 `pz=1000` 只回 100 条 —— 概念名单只剩前 100 个，导致 82 家涨停只落到 29 条归属、
主题全空。按 `pn` 翻到 `total`（531）为止。

### 4. 历史自建：每日快照 + 启动回补

东财涨停池的回溯窗口实测只有 **约 20 个自然日**（20261015 及更早一律空），
所以历史必须自己攒：每日收盘定稿写 `data/limitup.db`，启动时回补缺口，
**连续 3 个空日期即停**（再往前上游本来就没有）。
历史日期**不写资金四列** —— `clist` 给的是"当下"的钱，标到上周五头上是错的；
只有「最新交易日 + 数据日期 ≤ 4 天」时才补一次（覆盖周末/小长假）。

### 5. 口径近似（不是经传的专有算法，页面上不要当成结论）

- **主题等级**按**当日涨停家数**分档（0~3 / 3~5 / 5~10 / 10~15 / 15 以上），
  与色条一致；单元格右上角的数字才是近 20 日累计。
- **扩张** = 当日涨停数 > 前 5 日均值 × 1.5；
  **高潮** = 当日涨停数创近 20 日新高（且 ≥ 3 家）；
  **三共振** = 首板、连板、炸板三项同时高于各自前 5 日均值。
- **产业链 / 事件性 / 风格性** 按关键词近似归类（风格：高股息/低价/破净/次新/国资…；
  事件：业绩/涨价/中标/并购/政策…；其余归产业链）。
- **全市场涨停数**用东财 `tc`，与经传略有差异（同日实测 32 vs 33，ST/北交所口径）。

### 6. 采集节奏与自包含

`services/limitup.py` 完全自包含：只读写 `data/limitup.db`，不碰 `board_flow.db`，
不参与期权链路（与 `services/wangwang.py` 同一套路）。`app.py` 里
`asyncio.create_task(lu_svc.run_forever())`：盘中每 2 分钟刷当日，15:05 定稿锁定。

## 后果

- 新增一级导航「涨停棱镜」（`#/limitup`），侧栏图标 `Flame`。
- 接口 `/api/limitup/overview|prism|pool|health|refresh`，全部 `{error}` 降级不 500。
- 纯函数（分档、扩张/高潮/共振、矩阵构建、噪音过滤、主题聚合）在
  `tests/test_limitup.py`，不触网、不读时钟、不写盘。
- 页面是**浅色**主题（沿用项目 2026-10-13 起的浅色规范），只复刻信息结构。
- 已知局限：前 15~20 个交易日才有数据；主题体系是东财概念，会出现「央国企改革」这类
  宽泛主题靠前；涨停原因依赖同花顺，被 WAF 拦时显示行业名。

## 2026-11-07 迭代：扩充涨停口径 + 综合排名配色

用户要求：① 周期表展示每日前 **15** 名（原来 10）、单元格加高、卡片加高；
② 单元格底色统一用**蓝色**并整体压淡，颜色深浅表示「统计期间综合排名」而不是当日涨停数；
③ 选中态不用外框，直接**换红色底色**（同一主题在所有日期的格子一起变红，与源页面一致 ——
经传也是给该主题的每个格子描框）；
④ 筛选栏「三共振」右边加一个**「扩充涨停」**勾选：涨幅 > 9.9% 的个股也计为涨停。

### 两种口径同时落库

`lu_themes` 主键加 `mode`（`zt` / `ext`），`lu_meta` 加 `total_ext`，`lu_pool` 加 `sealed`：

- `zt`：东财涨停池（封板）—— 与之前完全一致，默认口径；
- `ext`：涨停池 ∪ 涨幅 > 9.9% 的个股（`sealed=0`，即"涨超 9.9% 但没封板"）。
  来源是一次 `clist` 全 A 按 `f3` 降序（首屏 100 条就到 4% 以下，最多 4 页），
  **剔除 `N`/`C` 开头的新股**（上市首日/次 5 日无涨跌幅限制，+120% 不是涨停）。
  前端个股池里这类票打「未封板」标记，连板数按 1 显示、封板金额留空。

两种口径**同时采集同时落库**，切换勾选不需要重跑上游，只是换 `mode` 读。

### 综合排名算法（颜色深浅）

```
score(b) = Σ_d  zt(b, d) × 0.9^(距今天数)
heat(b)  = (score(b) / max_score) ** 0.75      # 0~1
alpha    = 0.08 + 0.42 × heat                  # 蓝底透明度
```

- 0.9 的日衰减让**近期**的涨停更有分量（10 个交易日前权重约 0.35）；
- **不能用名次百分位**：概念有 130+ 个、尾部全是 1~2 家的噪音主题，按名次算的话
  前 15 名会全挤在 0.95~1.0，深浅根本看不出区别（实测踩过）；改成按分数归一并开 0.75 次方，
  首位 1.0、第 5 名约 0.75、尾部 < 0.1，层次清楚。
- 纯函数 `composite_rank()`，单测覆盖「近期权重更高」「首名恒为 1.0」「前几名有层次」。

### 性能：概念归属按代码缓存

`ext` 口径把每天待查概念的股票数从 30 只抬到 40~120 只，逐日回补会很慢。
新增 `lu_concepts(code, data, ts)` 表缓存 7 天 —— 概念成分本身就是"当前"口径、与日期无关，
每只股票一辈子只查一次（7 天过期刷新）。

## 2026-11-07 迭代二：历史补到 30 日 / 排除名单 / 点单元格切日期

### 1. 历史长度：东财只够 15 个交易日，更长用同花顺兜底

东财涨停池实测只能回溯到 **20261019**（19 个自然日），再往前一律空。
同花顺 `limit_up_pool` 至少到 **20260105**，所以 `collect()` 加了一条兜底：
`_zt_pool()` 为空时改调 `_ths_pool()`，并把 `lu_pool.src` 标成 `ths`。

- 同花顺给 `high_days`（"3天3板"）、`order_amount`（封单额）、`reason_type`（涨停原因），
  与东财字段同构，主题维度仍然用东财概念（不受影响）；
- **同花顺没有历史炸板池**（`open_limit_up` 接口 404），所以老日期的「板块炸板/烂板」
  为空、三共振判定不成立——这是上游极限，不是 bug；
- **扩充涨停只在实时采集那天有效**：`clist` 给的是"当下"的涨幅，套到历史日期上一定是错的。

`_backfill(N)` 的语义改成「库内不足 N 个交易日就补够」（原来是每次补 N 个），
连续空日期阈值放宽到 8（国庆连休有 5 个工作日是空的），空日期隔 1.2s 重试一次
（同花顺连续请求会被限流，曾导致 7 个日期静默失败），每个日期之间 sleep 0.4s。

### 2. 排除名单：`data/limitup_exclude.json`

默认 `["央国企改革"]`。**读时过滤**（`excluded_names()`），改完刷新页面即生效、不用重采。
在算热度和建矩阵**之前**就剔掉，否则剩余主题的颜色会被这个巨无霸压扁。

### 3. 点单元格 → 右侧切到那一天

周期表的**窗口锚点**（顶部日期选择器，`date`）与**右侧面板看的日期**（`cellDate`）分开：
点中间某一列不会让整张周期表跳走，只把主题榜/个股池/棱镜切到那一天。
主题榜数据来自新的 `GET /api/limitup/themes?date=` （周期表那次 `overview` 只给窗口最后一天，
不够用）。

### 4. 踩到的坑：历史日期的概念行把 board 写成中文名

`_write_snapshot()` 的 `boards` 参数同时承担两件事：写 `lu_boards` 资金快照、把概念名映射成
板块代码写进 `lu_stock_concepts.board`。历史回补用 `with_funds=False` 时曾把 `boards` 传成空字典，
结果概念行的 `board` 退化成"西部大开发"这种中文名，而 `lu_themes.board` 是 `BK0590`，
**按主题筛个股池永远筛不到**（历史日期点进去个股池全空）。
现拆成 `boards`（永远传全量）+ `write_boards`（只控制资金表），并补了回归验证。

## 2026-11-07 迭代三：主题分级 / 三种排序口径 / 「涨停分析」弹窗

### 1. 主题等级（全部 / 一级 / 二级）

经传是自有主题体系，我们只有东财 531 个平铺概念，所以用**板块有多宽**当粒度代理：
`f104 + f105 + f106`（上涨 + 下跌 + 平盘家数）≈ 成分股数，`≥ LEVEL_PRIMARY_MIN(150)` 算
**一级主题**（大方向：光伏概念、新能源车），否则算**二级主题**（细分：HJT 电池、减速器）。
成分数存 `lu_board_meta`（跨日期共用一份）。**缺元数据的板块两个等级都保留**，
不能因为没抓到就悄悄把主题丢掉。

### 2. 三种排序口径

| 选项 | 含义 | 落地 |
|---|---|---|
| 按炒作涨停（默认） | 一票一主概念（所属概念里 BOARD_RANK 最靠前的那个） | 另一种聚合结果，落库成 `*_hot` mode |
| 按板块涨停 | 一票计入它所有命中概念（数字更大更泛） | 原有 `zt` / `ext` mode |
| 按涨幅 | 板块口径的集合，排序改用当日板块涨幅 | 只影响排序；历史日期没有涨幅 → 回落按涨停数 |

所以 `lu_themes.mode` 有 4 种：`zt`、`ext`、`zt_hot`、`ext_hot`（两种底池 × 两种归集）。

### 3. 「主题猎手-涨停分析」弹窗

右上角按钮打开，内容：一句话解读（红字）+ 概述（灰字）+ 每个热门板块的**炒作原因**
+ 该板块涨停个股的**详细涨停原因**。

- **个股详细原因**：同花顺 `block_top` 的 `reason_info`（300~400 字分点说明，正是弹窗要的长文本），
  一次请求/天，历史也能取（实测 6 月都有）→ 落 `lu_pool.reason_detail`；
- **个股主力净额**：`ulist.np` 批量一次拿 30~40 只（`f62`），落 `lu_pool.main_net`；
  **只有实时采集当天有值**（ulist 给的是当下的钱），历史日期显示 `-`；
- **炒作原因**：整份解读**一次**大模型调用（`llm.complete()`，新加的通用文本补全，
  与决策链共用 REST + CLI 兜底），结果按 `日期+mode` 缓存到 `lu_brief`。
  提示词里写了硬约束：只能归纳给出的个股原因、不得引入未提及的宏观事件、
  **没有共同主线就明说"暂无统一主线"**（第一版没写这条，模型给"油气资源"编了 IRA 政策）。
  大模型不可用/超时 → 规则拼接（把该板块涨停股的原因标签去重取前 3）。
- 缓存命中要判 `theme_reasons`（payload 里**不含**个股列表，个股每次现查）；
  第一版误判 `themes` 导致每次开弹窗都重调大模型。

### 4. 个股池四个标签页全部按当前板块过滤

不再有"全市场"页：板块涨停（按封单额）/ 炒作涨停（同批个股按连板高度→涨幅）/
板块炸板 / 板块烂板，四个页都只看当前选中板块。名称列固定 104px + `whitespace-nowrap`，
保证「新亚制程」这类名字不折行。

## 2026-11-07 迭代四：「涨停分析」按钮归位 + 只看当前板块

- 按钮从顶部工具栏挪到**个股池卡片标题右侧**（`个股池 · 光伏概念 ｜ 涨停分析 ｜ 四个标签` 同一行）；
- 弹窗改为**只分析当前选中的板块**：`GET /api/limitup/brief?theme=BKxxxx`，
  解读缓存键扩成 `(theme, date, mode)`；
- 指定板块时**排除名单与等级筛选让位**（用户点名要看，就不能被过滤掉）；
- 若该板块在炒作口径下没有记录（从不作为"主概念"的宽泛板块，如央国企改革会被排除、
  或全市场都拿它当副概念），自动**退回板块口径**再查一次，保证点哪个板块都有结果；
- 提示词随 scope 切换：单板块时只要求概述这一个板块的主线，不再凑"3-4 个板块"的标题句式。

## 2026-11-07 迭代五：「涨停分析」改用设置里的大模型 API（不依赖 opencode）

用户要求：涨停分析不要依赖 opencode，直接用大模型 API，并在设置里填写必填参数。

**职责重新划分**：

- 后端 `brief()` **不再调用任何大模型**（删掉了 `llm.complete()` 与 `lu_brief` 缓存表），
  只负责把数据拼好：板块、涨停股、`reason_detail` 详细原因、`main_net`，
  外加一份**规则兜底文案**（`headline` / `summary` / 每个板块的 `reason_text`）；
- 前端 `BriefDialog` 读到「设置 → 大模型」里的配置（Base URL / 模型 ID / API Key，
  支持浏览器直连或看板后端代理）后，用 `browserChat()` 调一次模型生成解读，
  解析成 `{headline, summary, themes[{name, reason}]}` 覆盖显示，并按
  `日期|口径|排序|板块` 缓存在 localStorage（重解读会清缓存重调）；
- 没配置 / 调用失败 → 直接显示后端的规则文案，并给「去设置大模型」按钮（`openLlmSettings()`）。

这样每个设备用自己的 key，配置不出服务器、不进日志，也不消耗项目里的免费模型额度。
提示词沿用之前的硬约束（只能归纳给定个股原因、没有共同主线就明说、不得新增板块）。

## 2026-11-07 迭代六：弹窗重排 + 周期表角标改「近 7 日」

### 1. 角标统计窗口 20 日 → 7 日

周期表单元格右上角的数字原来是「近 20 日涨停总数」，改成**近 7 个交易日**
（`BADGE_DAYS = 7`），字段也从 `count_20d` 改名成 `count_7d`（前后端一起改）。
注意：**扩张/高潮/三共振的判定窗口没动**（高潮仍是"创近 20 日新高"），只有角标这个数字换了窗口。

### 2. 「涨停分析」弹窗排版（ReUI）

- 宽度 720 → **980px**（`w-[min(96vw,980px)]`）；
- 字号整体上调：标题 14 → 16px，`涨停解读` 15 → **18px/600**，正文字号 12 → 14px，
  炒作原因与个股原因 11 → **13px / 行高 24px**（长文本更好读）；
- 关键信息用 ReUI `Badge` 表达：板块名（primary-light）、涨停家数、涨幅（涨红/跌绿）、
  主力净额、连板数（≥3 红 / 2 黄 / 首板灰）、模型名；
- 每个板块用 ReUI `Frame variant="inverse" spacing="sm"` 包裹，标题行放板块名 + 三个徽标；
- 个股从密集表格改成**两列卡片网格**（`md:grid-cols-2`），每张卡片：名称 + 连板徽标 + 代码 +
  右侧主力净额（红涨绿跌），下面一行是详细涨停原因；

## 2026-11-07 迭代七：口径对齐（主题榜家数 = 个股池行数）

**现象**：绿色电力 个股池列出 5 只，主题榜「涨停」显示 3 家，用户判定数据对不上。

**根因**：不是数据错，是两个口径混用 ——
- 主题榜默认排序 `按炒作涨停`，读的是 `lu_themes.zt_hot`（一票一主概念）→ 3；
- 个股池「板块涨停」读的是板块口径（属于该板块就算）→ 5。

**决策**：**对外显示的"涨停家数"一律用板块口径**（= 个股池能列出来的家数），
排序口径（炒作/板块/涨幅）只决定**顺序**，不再决定数字。理由：同一个板块的家数不应该
随排序或标签页变化，否则用户永远会觉得对不上。

**实现**：
- 新增纯函数 `apply_board_counts(rows, counts)`（单测覆盖）：把显示数换成板块口径，**保持传入顺序**；
- `build_matrix` 支持 `rank` 字段：给了 rank 就按它排，不再按 zt 重排（否则炒作排序会被打回去）；
- 周期表 7 日角标也改用板块口径（避免"当日 5、7 日累计 3"自相矛盾）；
- 个股池「炒作涨停」tab **不再按主概念过滤**，只改排序（连板高度→涨幅）——
  曾试过过滤成 3 只，结果切标签页后 5 vs 3 又对不上，故放弃。

**验证**（ego lite 实机）：绿色电力/文娱消费/油气资源/消费电子概念/通信技术 五个板块 ×
「板块涨停」「炒作涨停」「扩充涨停 ON」三种状态，共 15 组对比，主题榜家数与个股池行数全部一致。

### 迭代七补：棱镜图与弹窗也要跟着换口径

上一轮只改了 `overview` / `themes_of`，**棱镜图标题和「涨停分析」弹窗仍读炒作口径**，
于是同一页出现「主题榜 5 家、棱镜标题 3 家、弹窗 3 家」。现在 `prism()` 的主题线
和 `brief()` 的主题数都改用 `base_mode`（板块口径），四处数字全部一致。
